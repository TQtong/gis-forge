# GeoForge 行政区范围选择器：产品与交互设计

## 1. 产品目标与成功标准

用户应能在一个页面内完成“找到行政区—确认范围—选择点/线/面—校验—下载 GeoJSON”的闭环。成功标准如下：

- 名称和 adcode 能定位国家、省、市、区县；
- 地图点击与搜索结果始终指向同一个行政区对象；
- 下钻、返回和聚合目标层级不会产生歧义；
- 点、线、面共享相同的行政区集合和 WGS84 面源数据，并能通过拓扑元数据双向转换；
- 下载前能看到原始/转换边界和控制点校验结果；
- 数据不完整、转换失败或校验无法执行时，不允许静默生成文件。

## 2. 页面信息架构

桌面端采用“地图主区 + 右侧配置区”，工具自身占满现有地图工作区，不新增独立工具市场。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 行政区搜索（名称 / adcode）                       数据源与更新时间 │
├──────────────────────────────────┬──────────────────────────────────┤
│ 中国 > 湖南省 > 长沙市           │ 1. 当前选择                      │
│                                  │    名称、adcode、层级、父级      │
│          WebGPU 地图             │ 2. 范围粒度                      │
│    原始/转换边界、控制点叠加     │    自身 / 市 / 区县              │
│                                  │ 3. 目标 Feature 形态             │
│                                  │    面 ⇄ 线 ⇄ 点                   │
│                                  │ 4. WGS84 控制点与校验结果        │
│                                  │ 5. 下载 GeoJSON                  │
├──────────────────────────────────┴──────────────────────────────────┤
│ 状态：数据获取 / 转换 / 校验 / 可下载                              │
└─────────────────────────────────────────────────────────────────────┘
```

移动端保持同一功能，将右侧配置区改为地图下方抽屉；搜索与面包屑固定在顶部，下载按钮固定在抽屉底部。地图最小高度为 45vh，表单控件触控高度不小于 44px。

## 3. 选择与下钻

### 3.1 初始状态

- 初次进入加载全国目录和全国省级边界预览；
- 默认选中“中华人民共和国（100000）”，目标粒度默认为“省”，Feature 默认为“面”；
- 未加载完目录时可显示地图底图，但搜索、下钻和下载禁用。

### 3.2 地图交互

- 单击未选中区域：选中该区域，更新右侧信息，不改变层级；
- 再次单击当前已选区域：若存在子级则下钻一级；若为区县则保持选中；
- 单击其他区域：直接切换选择；
- 指针悬停只显示高亮和名称，不触发网络请求；
- 拾取采用异步 GPU Color-ID，等待期间保留上一次选择，避免界面闪烁。

### 3.3 搜索

- 输入纯 6 位数字时按 adcode 精确匹配；其他输入按规范化中文名称匹配；
- 先显示精确匹配，再显示前缀匹配，最后显示包含匹配；
- 同名结果必须展示完整层级路径，如“鼓楼区 / 江苏省 / 南京市”；
- 选择搜索结果后自动加载其父级视图、选中要素并缩放到边界；
- 搜索只基于已经缓存的完整目录，不为每次键入请求远端接口。

### 3.4 面包屑

面包屑来自目录中的 `parentAdcode` 链。点击任一级后加载该级的直接子级预览，并将该级设为当前选择。直辖市、港澳台均遵循 Provider 返回的父子关系，不在 UI 中伪造中间层。

## 4. 范围粒度与聚合

| 当前选择 | 可选导出粒度 | 行为 |
| --- | --- | --- |
| 国家 | 自身、省 | 全国面自身，或全国所有省级 Feature |
| 省/直辖市 | 自身、市、区县 | 普通省按目录向下聚合；直辖市可直接聚合区县 |
| 市 | 自身、区县 | 输出当前市，或其全部区县 |
| 区县 | 自身 | 输出当前区县 |

聚合表示把每个目标行政区作为独立 Feature 放入一个 FeatureCollection，不做 dissolve。所有预期子级都成功获取后结果才是 `complete`；否则展示缺失清单，下载按钮禁用。全国→市和全国→区县首期不提供，避免巨量请求与浏览器内存失控。

切换粒度时取消上一次尚未完成的聚合任务。新任务完成前继续显示当前已确认边界，但明确标注“正在准备新范围”，不能用旧数据执行新下载。

## 5. 点、线、面几何转换

DataV `areas_v3` 下载结果固定为 Polygon/MultiPolygon 面。页面中的“目标 Feature 形态”调用几何转换器生成点或线，不使用目录里的中心点。切换目标形态会更新预览和下载统计，行政区集合和 WGS84 坐标不会改变，但 Feature 数会随环数和顶点数变化。

### 5.1 面 → 线

- Polygon/MultiPolygon 的每个外环、孔洞环分别输出一个 `LineString` Feature；
- 坐标保留原始环顺序和首尾闭合点；
- 每条线携带 `sourceFeatureId`、`partIndex`、`ringIndex`、`ringRole` 和 `closed: true`；
- 一个行政区可以产生多条线，不能把不同部件或孔洞拼成一条线。

### 5.2 线 → 点

- 每条线的每个有效节点输出一个 `Point` Feature；
- 对闭合环省略末尾与首点重复的那个 Point，并以 `closed: true` 表示恢复时需要闭合；
- 每个点携带所属线、面部件、环、`vertexIndex` 和 `ringVertexCount`；
- 点是边界顶点，不是行政区质心、中心点或内部代表点。

### 5.3 面 → 点

严格等价于“面→线→点”，使用同一转换器和同一顶点去重规则。直接调用和两步调用必须生成相同的 Feature ID、坐标、顺序与拓扑属性。

### 5.4 点 → 线

- 只接受含完整拓扑元数据的点集合；
- 按 `sourceFeatureId/partIndex/ringIndex` 分组，再按 `vertexIndex` 排序；
- `vertexIndex` 必须从 0 连续到 `ringVertexCount - 1`，不得重复或缺号；
- `closed: true` 时追加首点形成闭合 LineString；缺少元数据时明确报错，不按空间邻近猜顺序。

### 5.5 线 → 面

- 只接受闭合且带 `partIndex/ringIndex/ringRole` 的线；
- 按行政区和 part 分组，`outer` 环创建 Polygon 部件，`hole` 环归属对应 part；
- 校验每个 part 恰有一个外环，孔洞闭合且至少有 4 个坐标；
- 多个 part 恢复为 MultiPolygon，单个 part 恢复为 Polygon。

### 5.6 点 → 面

严格等价于“点→线→面”。任何中间校验失败都终止转换，不通过凸包、凹包、缓冲区等推测算法补面。

### 5.7 可逆性

工具自身生成的点、线必须能够通过拓扑元数据恢复成与标准化面坐标一致的 Polygon/MultiPolygon。坐标值、环顺序、孔洞归属和行政区属性是往返测试的比较内容。GeoJSON Feature 的拆分数量可以不同，但恢复后的面拓扑必须相同。

## 6. 控制点校验交互

用户输入 WGS84 经度、纬度，可选填写预期关系（区域内、区域外、边界附近）和边界容差。点击“执行校验”后：

1. 地图叠加红色原始边界、绿色 WGS84 边界和高亮控制点；
2. 面板展示转换前后各自的内外关系、最近边界距离和距离变化；
3. 展示通过、警告、失败或无法判定；
4. Feature 形态切换不重新计算校验，因为校验固定使用标准化面边界；这里的“几何转换”与 GCJ-02→WGS84 的“坐标系转换”是两条独立流程。

控制点详细算法和状态规则见[控制点校验设计](./GeoForge_AreaSelector_Validation_Design.md)。

## 7. 下载行为

下载按钮仅在以下条件全部成立时启用：

- 当前范围数据完整；
- 坐标系转换与目标几何转换均完成并通过结构校验；
- Feature 模式已选择；
- 不存在进行中的聚合或转换任务。

校验不是强制下载门槛：用户没有控制点时仍可下载；如果已经执行校验且结果为失败，下载前必须出现二次确认，并将校验摘要写入 FeatureCollection 的顶层扩展元数据。文件名固定为：

```text
{adcode}_{normalized-name}_{target-level}_{feature-mode}_wgs84.geojson
```

示例：`430000_hunan_district_polygon_wgs84.geojson`。名称使用安全的 ASCII slug；adcode 和中文名称仍完整保存在 Feature 属性中。

## 8. 状态和错误反馈

| 状态 | 界面行为 |
| --- | --- |
| `idle` | 可搜索和选择，下载禁用 |
| `loading-catalog` | 显示目录加载进度，禁止交互选择 |
| `loading-boundary` | 显示骨架/进度，可取消，不清除已确认地图 |
| `processing` | 展示转换或聚合进度，下载禁用 |
| `ready` | 可切换 Feature、校验和下载 |
| `partial` | 列出失败子级，允许重试，禁止下载 |
| `error` | 展示结构化错误码、可读原因和重试入口 |
| `gpu-unavailable` | 隐藏地图预览，保留搜索、表单、计算和下载 |

错误不得只输出到控制台。网络失败、CORS、数据解析、坐标非法、Worker 超时、缓存损坏和 GPU 设备丢失必须分别呈现可操作提示。
